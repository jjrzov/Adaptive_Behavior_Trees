\section{Problem Formulation}
\label{sec:problem_formulation}
    % Problem Motivation Restated
    Consider a robot in a packaging warehouse tasked with scanning a package and leaving it in either bin~A or bin~B.

    To complete the task, the robot needs to scan the package and place it into either of the two bins, and neither half of the mission can be altered without changing the overall objective. (more active voice, clarity on the last half of the sentence.)
    
    % Show that current formalism can't write disjuncts
    Following \cite{cai2021}, a condition $c$ is a set of literals, and $c$ holds in state $s$ when $c \subseteq s$.
    The item $c$ is defined as a subset of $s$ for which every literal of $c$ is required to be present; thus, a condition is inherently composed of conjunctions because these express that all of the literals hold, and never that any one of them does.
    Problem~\ref{prob:one} takes a single condition as its goal, with subset containment as the only satisfaction test.
    A goal may therefore carry any number of literals, but its structure is fixed.
    The formalism has no operators for combining goals, so any structured goal must be decomposed into separate planning problems before planning begins.
    
    % Introduce grammar for goals
    Since a single condition cannot express the warehouse task, the goal is lifted from a condition to a structured expression over conditions.
    \begin{equation}
        g ::= c \mid g \wedge g \mid g \vee g
        \label{eq:goal-grammar}
    \end{equation}
    Definition \eqref{eq:goal-grammar} is recursive as each operand is itself a goal, allowing goals to nest to arbitrary depth.
    Each goal induces a success region, the set of states satisfying it, defined over the same structure.
    \begin{equation}
        S_c = \{s \in S : c \subseteq s\}, \qquad
        S_{g_1 \wedge g_2} = S_{g_1} \cap S_{g_2}, \qquad
        S_{g_1 \vee g_2} = S_{g_1} \cup S_{g_2}
        \label{eq:success-region}
    \end{equation}
    The base case is the satisfaction test of Problem~1.
    Conjunction intersects the regions of its operands and disjunction unions them.
    The operands of a disjunction are its disjuncts.
    
    The warehouse goal is written $\pred{AND}(\pred{scanned}, \pred{OR}(\pred{box\_at\_A}, \pred{box\_at\_B}))$.
    When the grammar produces a goal with no operators, it is a condition in the sense of Problem~1.
    This reduction is proved in Section~\ref{sec:equivalence}.
    
    % State the modified Problem 1, aka Problem 1'
    Let $\mathcal{G}$ be the set of goals generated by \eqref{eq:goal-grammar}.
    \probprime keeps the tuple $\langle S, A, \mathcal{T}, s_0, g \rangle$ of Problem~1 and changes only the goal, from a single condition to $g \in \mathcal{G}$.
    \begin{problemprime}
        Given $\langle S, A, \mathcal{T}, s_0, g \rangle$ with $g \in \mathcal{G}$, build a BT $\mathcal{T}_s$ with actions from $A$ such that
        \begin{enumerate}[label=(\roman*)]
            \item $\mathcal{T}_s$ is finite time successful with region of attraction $R' \ni s_0$, and \label{cond:fts}
            \item $\mathcal{T}_s$ returns SUCCESS in state $s$ only if $s \in S_g$. \label{cond:status}
            % TODO: check the if and only if vs only if use in the statement
        \end{enumerate}
    \end{problemprime}
    
    % Why part 2 is added
    Condition~\ref{cond:status} restates the requirement of \probone that every state in the success region of $\mathcal{T}_s$ satisfies the goal.
    It is stated separately because the soundness argument of \cite{cai2021} does not extend to a structured goal (Section~\ref{subsec:inherited-scope}).

    % Define ROA over the goal structure not the root
    % TODO: Put defintion 2 in background
    For a goal $g \in \mathcal{G}$, the region of attraction of $\mathcal{T}_s$, written $R_g(\mathcal{T}_s)$, is the set of states from which ticking $\mathcal{T}_s$ reaches a state in $S_g$ in finite time.
    It is defined through $S_g$ rather than through the status of the root.
    When condition~\ref{cond:status} holds, $R_g(\mathcal{T}_s)$ is the region of attraction $R'$ of \ref{def:bt}, but a definition based on root status would count a tree that returns SUCCESS outside $S_g$ as succeeding from states it never brings into $S_g$
    
    % Brief Pipeline Overview and high level figure
    \input{figures/pipeline}
    Figure~\ref{fig:pipeline} shows the pipeline. 
    A structured goal $g \in \mathcal{G}$ is built into a base unified tree that represents the goal structure directly as behavior tree nodes.
    The expansion loop of Algorithm~2 then grows that tree, selecting a condition to expand, expanding it into sequence structures for the applicable actions, and pruning the result, until the tree can run from $s_0$. 
    The tree is then ticked during execution.
    
    % Summarize contributions / plan of the rest of the sections
    Unified goal trees are one construction satisfying \probprime.
    DNF compilation, which plans each conjunct of the goal separately and joins the resulting subtrees under a fallback node, is another.
    This chapter defines the first and describes the second, and Chapter~\ref{ch:results} compares them.

    The loop structure, the one-step expansion, and the tick semantics are inherited from \cite{cai2021}.
    Three stages are modified.
    The base tree is built from the goal structure rather than from a single condition node (Section~\ref{sec:unified_construction}), action selection additionally protects the literals that the other operands of a conjunction must achieve (Section~\ref{sec:interference}), and pruning is scoped to the branch a structure sits in (Section~\ref{sec:pruning}).

\section{Inherited Designs}
\label{sec:inherited_design}
    This section covers the parts of \cite{cai2021} that later sections build on.

    \subsection{Scope of the inherited results}
    \label{subsec:inherited-scope}
    Proposition~2, Lemma~1, and Propositions~5 and~6 are each stated for a goal that is a single condition, and each relies on that assumption.
    The primary tree of Algorithm~2 is one condition node, which is what anchors the induction in Lemma~1.
    Proposition~2 describes the region of attraction of an expansion relative to the one condition being expanded.
    Soundness holds because the success region of the root is the goal condition, so the tree returning SUCCESS and the goal holding are the same event.
    
    A goal $g \in \mathcal{G}$ built with operators has no single condition node standing for it.
    Its success region $S_g$ is composed from the regions of its operands, and a tree representing it has several goal conditions rather than one.
    The inherited results say nothing about such a tree.
    They are not contradicted by it, they simply do not reach it, and in particular nothing in them forces the root to succeed only within $S_g$.
    Whether the construction of Unified trees in Section~\ref{sec:unified_construction} satisfies condition~\ref{cond:status} of \probprime is taken up in Section~\ref{sec:interference}.

\section{Baseline: DNF Compilation}
\label{sec:dnf_compilation}
    % Why DNF?
    DNF compilation, the approach to disjunctive goals proposed in \cite{chen2024} and reviewed in Section~\ref{chen2024_section}, serves as the baseline against which the unified construction is compared.

    % How is a DNF tree constructed?
    A goal $g \in \mathcal{G}$ is first normalized into disjunctive normal form, producing a set of conjunctive sub-goals.
    Each sub-goal is treated as an independent instance of \probone, with the sub-goal as its goal condition, and is planned separately.
    The resulting trees are gathered under a fallback node, as described in \cite{chen2024}.

    \input{figures/dnf_base_tree}

    % How does DNF satisfy Problem 1'?
    Each subtree under the fallback is an instance of \probone, so each is sound for its own sub-goal by the results of Section~\ref{subsec:inherited-correctness}.
    The fallback succeeds when any one of its children succeeds, so the root succeeds exactly within the union of the sub-goal success regions.
    For a goal in disjunctive normal form that union is $S_g$, and the construction satisfies condition~\ref{cond:status} of \probprime.

    % What are the three key properties of DNF trees?
    Two properties of this construction matter for what follows. 
    First, normalization is multiplicative across disjunctions, so the number of sub-goals grows with the number of $\pred{OR}$ operators in the goal.
    Second, sub-goals sharing literals are planned separately, so work common to them is repeated in each subtree.
    
\section{Unified tree Construction}
\label{sec:unified_construction}
    % What is the input?
    Before construction of a unified tree begins, preprocessing must occur on the goal input.
    The construction takes an expression of $\pred{AND}$ and $\pred{OR}$ operators over literals.
    Any operand nested under an operator of the same type is collapsed into its parent.
    An input such as $\pred{AND}(a, \pred{AND}(b, c))$ is collapsed to the equivalent goal $\pred{AND}(a, b, c)$.
    The expression is therefore normalized to a canonical form before any tree is built.

    \input{figures/unified_base_tree}

    % Operators to GoalType Conversions
    Representing an $\pred{AND}$ or $\pred{OR}$ operator in the tree requires a node that reproduces its semantics.
    A disjunction becomes a \texttt{GoalSelector} and a conjunction becomes a \texttt{GoalSequence}.
    Goal-structure nodes have the same semantics as an ordinary sequence and selector, but they are distinguishable from the composites introduced by expansion, such as the sequence structures of \eqref{eq:cattr}.
    Under an $\pred{AND}$, loose literals are merged into a single condition child regardless of their order in the goal, so they are regressed jointly.
    Each remaining operand is built recursively by the same rules.


    % How are sibling branches of a sequence protected?
    A \texttt{GoalSequence} whose children are expanded separately admits a failure the inherited construction cannot exhibit.
    The children of a \texttt{GoalSequence} are called siblings, and each is meant to achieve the literals of its own operand of the conjunction.
    An action introduced into one child's subtree may delete a literal that a sibling is meant to achieve, so the sequence may report SUCCESS in a state that does not satisfy the goal.
    To constrain this, the literals each sibling is meant to achieve are recorded and added to the protect sets of every condition in the remaining children's subtrees.
    Three modes are available.
    Off applies no protection, left protects only against earlier siblings of a \texttt{GoalSequence}, and symmetric protects every sibling against every other.
    Under nested operators, a condition beneath several \texttt{GoalSequence} nodes accumulates the protected literals of each in the left and symmetric modes.

    % How are nodes scoped per branch?
    Expansion in a unified tree acts on a tree containing several goal conditions rather than one, so a condition may be reachable from more than one disjunct.
    To keep each branch's expansion independent, conditions are scoped by the branch they sit under.
    The scope of a condition is found by walking up the tree to the nearest \texttt{GoalSelector}, and the child of that selector identifies the branch.
    The expanded set of \cite{cai2021} records which conditions have already been expanded so that duplicated work is avoided.
    In a unified tree a condition is identified by its literals together with its protect set and its scope, so the same literals may be expanded once per branch.
    Where no \texttt{GoalSelector} ancestor exists, no scope is assigned, so a goal containing no disjunction has a single scope across the whole tree.

    % Scope vs protect
    Scope and protect set are not redundant.
    Under $\pred{AND}(c_s, \pred{OR}(c_1, c_2))$ with left protection, the conditions of both branches carry the protect set $c_s$, and only their scope distinguishes them.

    % Brief intro into why unified trees at all?
    This construction represents the goal structure directly, so a problem yields one tree rather than $k$.
    A conjunct shared between disjuncts appears once rather than once per disjunct, as it would under DNF compilation.

\section{Equivalence in the Flat Case}
\label{sec:equivalence}
    % What is the scope of a flat case?
    A goal of the form $g = \bigvee_i c_i$, a disjunction of conditions with no nested operators, is called flat.
    For a flat goal, the two constructions produce the same tree, provided both are run to the same termination point.
    Section~\ref{sec:fixpoint} describes how this is enforced.

    \subsection{Equivalent Goal Shapes}
    \label{subsec:equivalent_goal_shapes}
    % State that the goals are of the same structure on DNF or Unified
    Normalization is the identity on a flat goal, since $g$ is already in disjunctive normal form.
    The sub-goals that DNF compilation plans are therefore the operands $c_i$ themselves.
    The unified base tree is a \texttt{GoalSelector} over $c_1, \dots, c_k$, and the DNF tree is a fallback over subtrees planned from those same conditions. 
    The two share their goal conditions and their top-level structure, and differ only in whether each $c_i$ is expanded in place or separately before assembly.
    The order of the branches affects only which disjunct is pursued first during execution, not the node set or the success region.

    \subsection{Order Independent Expansions}
    \label{subsec:order_independence}
    % Why does it not matter when an expansion happens
    Both constructions expand to a fixed point, so every viable condition is eventually expanded.
    For the resulting trees to coincide, the outcome of an expansion must not depend on when it occurs.
    This holds because expanding a condition produces a subtree determined entirely by that condition.
    \eqref{eq:action-selection} and \eqref{eq:cattr} reference only the literals of the condition and the actions available to achieve it, so when a condition is expanded is irrelevant to what the expansion yields.

    % Why does expansion branch order not matter
    As defined in the inherited expansion loop, the expanded set records which conditions have already been expanded.
    Were that set shared across branches, a condition expanded in branch $j$ would be skipped in branch $i$, and branch order would determine the result.
    Since a condition's scope is part of its identity in the expanded set (Section~\ref{sec:unified_construction}), its eligibility in branch $i$ is independent of what was expanded in branch $j$.
    DNF compilation reaches the same isolation by resetting the expanded set for each sub-goal.

    % What order independence means for later discussions of fixpoint
    Since expansion order is independent both within a branch and across branches, the node set of a branch at fixpoint, \ref{sec:fixpoint} is the closure of $c_i$ under expansion.
    The final trees are therefore independent of how expansions are interleaved during construction.
    
    % What interleaving independence means for DNF vs Unified
    The closure of $c_i$ in the unified tree is therefore exactly the subtree DNF compilation builds for $c_i$.
    Since this holds for every branch of a flat goal, the two trees contain the same nodes up to the class of the root, and $R_g(\mathcal{T}_{\text{unified}}) = R_g(\mathcal{T}_{\text{DNF}})$.

    % A note on traversals
    Since order is inconsequential in the construction of the tree when expanding to fixpoint the same flat goal yields equivalent trees under any traversal that expands every viable condition not already in the expanded set.
    Traversals affect only which condition is expanded next, so traversal choice matters for planning cost and for a tree produced by early termination, not for a fixpoint tree.

    % Reduction case
    A goal with no operators after normalization, including a purely conjunctive one, yields a base tree that is a single condition, so both constructions produce the tree Algorithm~2 would have produced.
    A difference between the two constructions can arise only for a goal that is not flat, where an operator appears beneath one of the other type.
    
\section{Sibling interference under composed goals}
\label{sec:interference}
    % How soundness is not inherited
    As stated in Section~\ref{subsec:inherited-scope}, soundness holds for a tree with a single goal condition because the success region of the root is that condition.
    Under a \texttt{GoalSequence} the root's status is the conjunction of its children's statuses, and each child's status is computed against its own condition.
    A child's status is recorded when that child is ticked, so a child reporting SUCCESS establishes only that its condition held at that point in the tick, not that it holds when the sequence reports its own status.
    This failure is called sibling interference, in which an action in one sibling's subtree deletes a literal that another sibling is meant to achieve, after that sibling has already reported SUCCESS within the tick.

    % An example of sibling interference
    The following problem exhibits the failure.
    Table~\ref{tab:interference-actions} gives the action database, and the tree is built from the initial state $s_0 = \{\pred{at\_hall}, \pred{door\_closed}\}$ and the goal
    \begin{equation}
      g = \pred{AND}(\pred{door\_closed}, \pred{OR}(\pred{at\_dock}, \pred{at\_bench}))
      \label{eq:interference-goal}
    \end{equation}

    The attributed condition of \texttt{move\_to\_dock}, $\{\pred{at\_hall}, \pred{key\_held}\}$, does not hold in $s_0$, while that of \texttt{move\_to\_bench}, $\{\pred{at\_hall}\}$, does, so the loop stops after these two expansions.

    % How the violation happens with an example
    The action selected for $\{\pred{at\_bench}\}$, \texttt{move\_to\_bench}, deletes \pred{door\_closed}, which is the goal literal of the sequence's first child.
    Within a single tick the condition $\{\pred{door\_closed}\}$ is ticked first and returns SUCCESS.
    The sequence advances to its second child, where the dock branch fails because \pred{key\_held} does not hold, and the selector runs \texttt{move\_to\_bench}, removing \pred{door\_closed} from the state.
    The second child returns SUCCESS, so the sequence returns SUCCESS.
    The first child is not revisited within that tick, and the state at the end of the tick does not satisfy $g$.
    Re-evaluation occurs on the following tick, which reports FAILURE, but the root has already reported SUCCESS from a state outside $S_g$, violating condition~\ref{cond:status} of \probprime.

    % How the inherited c_attr allows this
    The violation follows from the scope of the inherited expansion step.
    The attributed condition of \eqref{eq:cattr} is computed from one condition and one action, and refers to nothing outside that pair.
    An action satisfying \eqref{eq:action-selection} for the second child's condition may therefore delete literals belonging to the first, since the selection test requires only that the action leave the condition being expanded intact.
    In the example, \texttt{move\_to\_bench} is selected for $\{\pred{at\_bench}\}$ because it adds \pred{at\_bench}, and it passes the second test because \pred{door\_closed} is not a literal of $\{\pred{at\_bench}\}$.
    Its attributed condition $\{\pred{at\_hall}\}$ records what the action requires and nothing of what it destroys.

    % What are the general criteria for a violation in soundness to happen?
    The failure requires a goal containing a \texttt{GoalSequence} whose children are expanded separately, such as a conjunction of literals alongside a disjunction, together with an action available to one child whose $del$ set intersects a sibling's goal literals.
    How often those conditions are met depends on the size of $del$ sets relative to the literal domain, which is examined in Section~\ref{sec:results_interference}.   % TODO: Update ref

    % How protect makes problematic actions unselectable
    The protect sets of Section~\ref{sec:unified_construction} close this by extending \eqref{eq:action-selection}.
    An action is selected only if it also leaves the protected literals of the condition intact, so an action whose $del$ set meets a sibling's goal literals is never selected for that branch.
    In the example, \pred{door\_closed} is added to the protect set of every condition beneath the selector, which makes \texttt{move\_to\_bench} not selectable for $\{\pred{at\_bench}\}$.
    The \pred{at\_bench} branch then has no expansion available, and the loop continues with the \pred{at\_dock} branch, which reaches $\{\pred{at\_hall}\}$ through \texttt{pick\_up\_key} and \texttt{move\_to\_dock} without deleting \pred{door\_closed}.
    Table~\ref{tab:interference-protect} reports the two configurations.

    % Soundness under left protection, stated
    The protect sets close this failure in general, not only in the example.
    The result is stated under the assumptions of \probprime, which keeps the state and action model of \probone unchanged.
    Two of those assumptions carry the argument.
    The status of a behavior tree is a function of the state alone (\ref{def:fts}), so its composites carry no memory and every child's status is recomputed on every tick.
    The effects of an action take place when the action succeeds (\ref{eq:action-effect}), which is read here as taking effect at the moment it reports SUCCESS, so that the remainder of the tick is evaluated against them.
    The state therefore changes during a tick only through the actions the tree runs in that tick, and a disturbance acts between ticks as a change of the state the next tick starts from.

    % Notation used in the proof
    For a goal $h \in \mathcal{G}$, let $L(h)$ denote the set of literals appearing in $h$.
    Under left protection, every condition beneath the $j$-th child of a \texttt{GoalSequence} with children $h_1, \ldots, h_m$ carries a protect set containing $\bigcup_{i<j} L(h_i)$, and expansion copies that protect set to every condition it introduces (Section~\ref{sec:unified_construction}).

    \begin{proposition}[Soundness under left protection]
    \label{prop:left_soundness}
        Let $\mathcal{T}_s$ be a unified tree built with left protection for a goal $g \in \mathcal{G}$, under the assumptions of \probprime.
        If the root of $\mathcal{T}_s$ returns SUCCESS on a tick, the state resulting from that tick lies in $S_g$.
    \end{proposition}

    \begin{proof}
        The proof rests on three observations.

        \emph{Success regions are preserved by actions that delete none of their literals.}
        If $s \in S_h$ and $s'$ contains every literal of $L(h)$ that $s$ contains, then $s' \in S_h$.
        This holds for a condition by $S_c = \{s \in S : c \subseteq s\}$, and it is preserved by the intersection and union of \eqref{eq:success-region}, so it holds for every $h$ by induction on the structure of $h$.

        \emph{A fallback produced by expanding a condition $c$ returns SUCCESS only in a state satisfying $c$.}
        The proof is by induction on the depth of the subtree.
        An unexpanded condition returns SUCCESS exactly when $c \subseteq s$.
        A fallback over $c$ and the sequence structures of its selected actions returns SUCCESS either because $c$ holds, or because some sequence structure over $c^a_{attr}$ and $a$ returned SUCCESS.
        In the second case the subtree over $c^a_{attr}$ returned SUCCESS first, so $c^a_{attr} \subseteq s$ by the inductive hypothesis, and nothing runs between that return and the action $a$.
        When $a$ reports SUCCESS the state is $s' = s \cup add(a) \setminus del(a)$.
        Since $c \setminus add(a) \subseteq c^a_{attr} \subseteq s$ by \eqref{eq:cattr}, and $c \cap del(a) = \emptyset$ by \eqref{eq:action-selection}, every literal of $c$ lies in $s'$.
        An action that reports RUNNING makes its sequence and fallback report RUNNING, so it never yields SUCCESS.

        \emph{A goal-structure node for a subgoal $h$ returns SUCCESS only in a state in $S_h$.}
        The proof is by induction on the structure of $h$, with the previous observation as the base case.
        A \texttt{GoalSelector} returns SUCCESS when some child $h_k$ does, and it ticks nothing further, so the state lies in $S_{h_k} \subseteq S_h$.
        A \texttt{GoalSequence} with children $h_1, \ldots, h_m$ returns SUCCESS only when every child returns SUCCESS on the same tick, in order.
        By the inductive hypothesis, child $h_i$ returns SUCCESS in a state in $S_{h_i}$.
        Because the composites carry no memory, the only actions run after that return and before the sequence returns are those beneath children $h_j$ with $j > i$.
        Each such action was admitted under a condition whose protect set contains $L(h_i)$, so it deletes no literal of $L(h_i)$.
        By the first observation, the state when the sequence returns still lies in $S_{h_i}$ for every $i$, and therefore in $S_h$.

        The root is the goal-structure node for $g$, or the fallback of its single goal condition when $g$ has no operators.
        Nothing runs after the root returns, so if it returns SUCCESS the state resulting from the tick lies in $S_g$.
    \end{proof}

    % What the proposition does and does not cover
    Symmetric protection admits a subset of the actions left protection admits, so the proposition holds for it as well.
    Without protection the third observation fails, since an action beneath a later sibling may delete a literal of an earlier one, which is the failure of Figure~\ref{fig:interference-tree}.
    The proposition concerns condition~\ref{cond:status} of \probprime alone.
    It says nothing about the states from which the tree reaches the goal, and the next paragraph shows that protection can only reduce them.

    Protection is not free.
    A plan that deletes a sibling's literal and later re-achieves it satisfies the goal, and the extended selection test forbids it.
    Soundness is therefore bought at the cost of completeness, and the two cannot both be guaranteed by this mechanism.
    Section~\ref{sec:results_interference} measures how much completeness that cost amounts to.

\section{Pruning}
\label{sec:pruning}
    \subsection{Pruning Definition}
    \label{subsec:pruning_definition}
    % How does pruning work?
    After an expansion occurs, a sequence structure whose condition is a superset of an already expanded condition is removed.
    The test applied to a candidate condition $c^a_{attr}$ is $e \subseteq c^a_{attr}$ over every condition $e$ recorded in the expanded set.
    The direction of the containment matters.
    When $e \subseteq c^a_{attr}$, every state satisfying $c^a_{attr}$ also satisfies $e$, which already reaches the goal, so removing the structure loses no states.
    Testing $c^a_{attr} \subseteq e$ instead would remove a condition that holds in states where $e$ does not, shrinking the region of attraction and breaking completeness.
    The same test appears in \cite{chen2024}.
    The completeness proof of \cite{cai2021} reasons in terms of $c_{exist} \subseteq c^a_{attr} \subseteq s$, so the subset direction is licensed by that proof even though the algorithm as published prunes only on an exact match.
 
    \subsection{Partitioning the Expansion Record}
    \label{subsec:pruning_and_protect}
    % What a recorded condition justifies
    The argument for the test rests on $e$ reaching the goal.
    In the tree of \probone every condition leads to the single goal condition, so any recorded condition justifies pruning, and any recorded condition may be skipped wherever else it appears.
    A unified tree has several goal conditions, and a recorded condition reaches only the goal of the subtree it was expanded in.
 
    % Siblings of a GoalSequence
    Across the children of a \texttt{GoalSequence} this matters directly.
    A condition expanded beneath one child reaches that child's goal, which says nothing about whether another child's goal is reached.
    If the record were shared between children, a condition expanded under one child would be skipped under another and left as a leaf there, and every state that relied on its expansion would be lost.
 
    % The protect set partitions the record
    The record is therefore keyed on a condition's literals together with its protect set (Section~\ref{sec:unified_construction}), and pruning compares only conditions with equal protect sets.
    Under left protection, every condition beneath a later child of a \texttt{GoalSequence} carries the goal literals of its earlier siblings, so conditions beneath different children carry different protect sets and never share an entry.
    Protection therefore separates the siblings of a \texttt{GoalSequence} in the record as well as in action selection.
    With protection off the protect sets are all empty, and only the branch scope of Section~\ref{subsec:pruning_scopes} keeps the children apart.
 
    \subsection{Pruning Scopes}
    \label{subsec:pruning_scopes}
    % Record and pruning are scoped together
    The branches of a \texttt{GoalSelector} share a protect set (Section~\ref{sec:unified_construction}), so they are separated by scope instead.
    Both the expanded record and the pruning test are scoped to the branch a condition sits in.
    The inherited rule instead records and prunes across the whole tree, and the two are scoped together.
 
    % Global pruning makes the tree depend on order
    Unlike siblings of a \texttt{GoalSequence}, a condition recorded in one branch of a \texttt{GoalSelector} does reach a goal that satisfies the selector.
    Sharing the record across branches is therefore not ruled out by the argument of Section~\ref{subsec:pruning_and_protect}, but it makes the tree depend on the order in which branches are expanded.
    Consider the goal $\pred{OR}(\pred{at\_A}, \pred{at\_B})$ over a domain in which both rooms are entered only from a shared intermediate room $M$.
    Each branch regresses its goal condition through a move out of $M$, so each holds a sequence structure whose attributed condition is $\{\pred{at\_M}\}$.
    Under a global rule, whichever branch expands $\{\pred{at\_M}\}$ first keeps the route through $M$, and the matching structure in the other branch is pruned.
    The resulting tree is no longer the closure of each branch, so the order independence of Section~\ref{subsec:order_independence} fails, and the flat goal no longer yields the DNF tree of Section~\ref{sec:equivalence}.
    Under scoped pruning each branch keeps its own route through $M$.
 
    % Decision
    Pruning is therefore scoped in the construction, so that each branch is expanded to its own closure whatever order the branches are visited in.
    The choice costs tree size, since a global record expands a condition shared by several branches only once.
    It is not needed for soundness, since the proof of Proposition~\ref{prop:left_soundness} does not depend on how the record is scoped.
 
    % Relating the pruning scope back to the overall design
    Both operators of the goal grammar break an inherited mechanism in the same way.
    The expansion step of \cite{cai2021} attributes a condition to one action without reference to anything else in the tree, and the expansion record treats every recorded condition as leading to the one goal.
    Neither is unsound for a goal that is a single condition, because such a goal has neither siblings nor branches.
    Composition introduces both, and each repair is local to the operator that introduced the problem, protection at the \texttt{GoalSequence} and scoping at the \texttt{GoalSelector}, with both entering the key of the expansion record.
